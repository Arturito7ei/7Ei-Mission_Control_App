## UI
- **V3 per-wake preflight cap + cheap-model config validation** (2026-07-07, epic MCA-84 story V3 — Visibility, closes epic V's cheap-wins tier / Paperclip gap G9): two small levers on the existing budget/cost code. **Per-wake preflight cap** — before an internal wake runs the LLM, bound its *worst-case* cost (full input context at the input rate + a full `max_tokens` completion at the output rate) and skip the wake if it would exceed a configured per-wake ceiling; the task is parked `blocked`/`needs_attention` with a plain-language reason and a durable `system_notice` comment (feeds the W1 recovery card). Distinct from the cumulative scoped budgets in `budget.ts` (those stop an agent once *total* spend crosses a limit) — this stops a *single* wake from being surprisingly expensive (runaway context, an accidental Opus swap). Runs before any expensive setup (RAG/Drive/memory fetches) so a capped wake costs nothing. Opt-in via `deployConfig.maxCostPerWakeUsd` (org-wide) with an optional `maxCostPerWakeUsd:<agentId>` override; null/≤0 = no cap. **Cheap-model config validation** — new `services/preflight.ts` pure helpers (`estimateWakeCost`/`preflightWake`/`parseCapUsd`/`validateModelConfig`/`validateRoster`) audit each agent's model: unpriced models (no `COST_RATES` entry — spend can't be tracked or capped) and models whose output rate exceeds the "cheap" threshold ($5/M output — passes Haiku/GPT-4o-mini/Flash/DeepSeek/Qwen-turbo/local, flags Sonnet/Opus/GPT-4o) are surfaced with reasons. Unpriced models under a cap are *allowed but flagged* `unbounded` (never silently block a working custom/local runtime). New `GET /api/orgs/:orgId/preflight` (cap + per-agent validation rows + warn count) and `PUT` (set/clear the cap in deployConfig). Web: `cockpit/PreflightSection.tsx` after Budgets — editable per-wake cap (accent CTA, never red) + per-agent audit rows (✓/⚠ iconed + amber, colorblind-safe) with est-max-wake-cost and flagged issues.
